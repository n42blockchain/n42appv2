## L1 — 钱包银行卡（Self-custodial Card）

> 对标 MetaMask Card（Mastercard + mUSD 返现，自托管扣款）。

### 架构分层
```
用户消费(POS/线上)  →  卡组织(Visa/Mastercard)  →  发卡行/Program Manager(BIN sponsor)
                                                          │
                                            授权钩子(Authorization webhook)
                                                          ▼
                            N42 卡后端(Card Orchestrator) ── 余额/限额校验 ── 链上结算
                                                          │
                              自托管扣款：用户钱包(AA + Session Key 限额授权) → 稳定币(L2)
```
- **自托管关键点**：消费瞬间从用户**自托管钱包**扣稳定币（非托管池）。实现路径 = **AA Session Key**：用户预授权一把「卡专用」Session Key，限定 `token=USDC/mUSD`、`spendingCap=月限额`、`allowlist=结算合约`、`expiry`；授权时实时校验并由 Session Key 签发结算交易。N42 已有 Session Key（`features/wallet/aa/`），是本项的工程基石。
- **返现**：结算后按比例发返现（稳定币/积分）；N42 已有 `points_repository`（积分）可承载。

### 接口契约（工程先行可写）
- `CardBridge`（抽象）：`requestVirtualCard()` / `getCardStatus()` / `setSpendingLimit(token, cap, period)` / `onAuthorizationHook(...)`；宿主注入真实实现。
- Session Key「卡策略」复用现有 `SpendingPolicy` 思路：`{token, dailyCap, monthlyCap, allowlist, expiry}`，纯逻辑可单测。

### 外部依赖 / 合规前置（红线）
- 发卡需 **BIN sponsor + Program Manager + 卡组织接入**（如 Marqeta/Stripe Issuing 类）；
- **KYC/AML、PCI-DSS、各地 EMI/MSB 牌照**（L5 前置）；
- 授权 webhook 的**实时性 SLA**（卡授权通常 <2s，链上结算需异步对账 + 预授权额度池兜底）。
- **结论**：工程可先交付 = Session Key「卡策略」纯逻辑 + `CardBridge` 接口 + 返现记账；**发卡/结算/合规需伙伴+牌照**，非仓内可完成。

## L2 — 原生稳定币（mUSD 式）

> 对标 MetaMask mUSD（Bridge + M0 协议发行）/ Trust Stablecoin Earn。

### 形态选择（三选一，按合规成本递增）
1. **合作贴牌**（最快）：接入第三方合规稳定币基础设施（M0 类）发「N42USD」，N42 不持牌、只做前端 + 分发 + 用例（卡返现载体 / 手续费抵扣 / 活期收益）。
2. **白标稳定币**：与持牌发行方共建，N42 掌品牌 + 储备透明度披露。
3. **自主发行**（最重）：自持牌 + 储备托管 + 审计 + 各地注册——战略级，监管风险最高。

### 与其他模块的接点（工程先行）
- **稳定币活期**（S1 已落地 `StablecoinEarnPage`）→ N42USD 作为默认活期标的。
- **卡返现**（L1）→ 以 N42USD 计返。
- **手续费抵扣** → Gas Paymaster（已有 AA Paymaster）接受 N42USD 付 Gas。
- 接口：`StablecoinIssuerBridge`：`mint/redeem 报价`、`储备证明(PoR)拉取`、`合规态查询`。

### 外部依赖 / 合规前置（红线）
- **发行方牌照 + 储备托管 + 月度审计/PoR**；各地稳定币法规（MiCA/美国稳定币法案等）。
- **结论**：工程可先交付 = `StablecoinIssuerBridge` 接口 + 把 S1 活期/Paymaster 接成「N42USD 就绪」；**发行/储备/合规须发行方+监管**。

## L3 — AI Agent 完整生态（EIP-8004 身份 + 自主支付）

> 对标 Trust AgentKit · Binance x402 · EIP-8004。**本项的「读+建议」雏形(M1)已可在仓内做**（见下「M1 已交付」），完整 agentic 代执行/自主支付才属远期。

### 分层（从可做到待基建）
```
[已交付] 钱包 AI 助手(只读+建议)  ──  WalletAssistantEngine(规则) + WalletAiChannel(复用 chat AI) + 钱包顶栏 UI 面板 + provider 只读快照
[中期]   受控代执行            ──  AI 规划 → 生成交易 → 用户每步签名（Session Key 限额半自主）
[远期]   自主支付/代理身份      ──  x402(HTTP 402 自主结算) + EIP-8004(代理链上身份注册)
```

### EIP-8004（代理链上身份）契约
- `AgentIdentity`：`{agentId, owner, capabilities[], reputation}`；链上注册表读写。
- N42 角色 = 代理的**资金层 + 身份层**：代理用 Session Key 受限额度出账，身份用 EIP-8004 注册可被验证。
- **护栏（安全第一，不可省）**：自主出账必须 `Session Key 限额 + 每步/限额授权 + allowlist + 风控（复用 `signature_decoder`/`mev_protection`/钓鱼检测）`，**严禁无授权自动签名**。

### 外部依赖 / 待基建
- **AI 通道**：钱包侧本无 LLM 通道——**M1 已用「复用 chat `AiService.completion`」打通**（见交付）。完整 agentic 需更强模型 + 工具调用编排。
- **x402 / EIP-8004**：协议适配 + 链上注册表（标准仍演进中，标「实验」）。
- **结论**：M1（读+建议）已交付可编译可测；受控代执行需在 Session Key 上做编排（中期，工程可做）；自主支付/代理身份待协议成熟。
