### 2.3 N42优势与差距

**N42 当前有证据支持的优势**:
- 默认配置覆盖 65 个网络，包含 EVM、Bitcoin、Cosmos、Solana、Tron、TON、Sui、Aptos、Polkadot、XRP、Filecoin、NEAR、Algorand、Tezos、Zilliqa、Stellar、Cardano、VeChain、MultiversX、Starknet 等 sender 家族

- 观察钱包已实现；竞品覆盖以各家当前官方资料为准，不再断言只有 Rabby/Zerion

**N42 差距**:
- 公开链数仍少于 Trust Wallet/OKX/SafePal 的宣称值；网络数量口径、默认启用范围和真实发送覆盖不同，不能只按数字横比
- **自定义 EVM 链**：真实生产入口是 `WalletChainAdd`（币列表「+」→ Add Tokens → Add custom chain），会验证 RPC 并持久化到钱包；余额和发送通过 `baseInfo.custom` 的 RPC override 直连自定义节点。⚠️ 有资金发送尚未真机闭环。`CustomChainService`/`AddCustomChainPage`/`_mergeCustomChains` 是另一套无导航、无写入方的并行死路径，不作为功能证据

### 3.1 N42 的 AA 实现 — 2026-07 逐项复核后需大幅收窄表述

此前"AA 领域深度领先/所有竞品中最完整"的定性经代码复核后**不成立**，逐项真实状态：
- **智能账户类型**: 创建页（`aa_account_create_form.dart`）当前实际可选 **Simple / Simple7702 / Safe / Biconomy / Kernel** 五类；旧报告中“四类”和“7702 不在 UI”均已过期 ✅
- **AA 批量交易**: `buildExecuteBatch` + 批量交易页 + DEX swap 的 approve+swap 原子批量，经真实 bundler 提交 ✅ 真实——这是 AA 侧最扎实的能力
- **EIP-7702**: ✅ **2026-07 已放行**——`simple7702_account.dart`/`eip7702_handler.dart`/部署器分支/factory 的 computeAddressForType(返回 EOA 地址)一直齐全,唯一缺口是创建页类型选择器硬编码列表不含 7702。已将 simple7702Account 加入选择器并放行 isAvailable(color/icon/描述 helper 早已覆盖该类型),用户现在可创建 EIP-7702 账户
- **Session Key**: 管理页真实可达（钱包页 → AA 首页 → Session Key 管理），可创建/撤销；**但 session key 只落本地 SQLite,从不上链安装,唯一的 AA 签名路径（`aa_transfer_handler.dart`）签名时也从不使用它**——是"只能管理、不产生任何效力"的摆设 ⚠️
- **Paymaster**: UserOp 打包管线支持 `setPaymaster`,但入口 gate 要求调用方传 `paymasterData`,**全仓所有真实调用方均不传——恒空**,`PaymasterService` 也从不真正调 `pm_getPaymasterData`。从无一笔真实 gas 代付发生 ⚠️
- ~~**单笔 AA 发送页是假实现**~~ → ✅ **2026-07 已修复**: 此前 `aa_send_page_logic.dart` 的发送逻辑是 `Future.delayed(2秒)` 后直接弹"成功"——不构建、不签名、不广播任何交易。现已接入与批量交易页同一条真实通道（`AATransferHandler`：构建 UserOperation → bundler 估 gas → 签名 → `eth_sendUserOperation` → 等回执）;若用户选了 Paymaster 代付则如实拦截提示"代付暂未开放"（因 Paymaster 本身无真实集成,静默按自付发送会造成意外扣费）
- **MPC (Web3Auth)**: 依赖已引入、创建页有导航,但 `Web3AuthMpcProvider` 零实例化、注册表恒空——**点击登录必报 "MPC provider not configured"**;`mpc_transfer_handler` 是零调用的 POC 桩(签的不是真实 RLP 交易、不广播) ❌

### 3.2 Passkey 与社交恢复 — ⚠️ 底层已实现，均无用户可达的 UI 入口

- **Passkey**: `lib/core/passkey/` 的 WebAuthn 注册/认证桥接（Android Credential Manager + iOS ASAuthorization）代码完整，AA 侧 `PasskeySignatureBuilder`（P-256 + RIP-7212 预编译）也已就绪；但**当前全仓没有任何主应用登录/解锁页面调用 `PasskeyService`**，`PasskeySigner`（AA 签名路径）同样零调用——生产签名实际走 `trustdart.signMessage` 的 ECDSA 路径。历史旧登录架构曾有 `passkey_login_button.dart`，后在 `d4d7456b` 删除；当前用户仍无法使用，但不能再据当前工作树推导为“历史从未接入”

### C. 当前工程优先级（2026-07-14）

1. **先完成有资金真机闭环**：AA 单笔/批量、Aave、LI.FI、ETH/Lido、自定义 EVM、加速/取消。代码存在但没有 txHash/回执证据的能力不得升级为“完整通过”。
2. **补齐产品入口前先补协议依赖**：Passkey 需要注册/认证/解锁 UX 与恢复策略；社交恢复需要实际模块合约；MPC 需要 Web3Auth 配置和真实交易实现；Paymaster 需要服务端与 `pm_*` 流程。它们都不是“一行注册”或“纯 UI 接线”。
3. **架构级缺口独立排期**：硬件钱包签名需合并硬件账户与主 `coinModels`；SOL/ATOM 质押需 StakeProgram/MsgDelegate 签名；Hyperliquid 下单需专用 EIP-712 action；Session Key 需链上模块安装与签名选择。
4. **维持真实能力边界**：红包是本地演示；治理、社交图谱、Loyalty 当前不可达；RPC 只有 HTTP 熔断器、没有自动端点切换；Web App 不可构建；JMT 是独立包。

N42 Wallet 当前可由代码、测试或真机证据支持的核心组合包括：**Matrix E2EE 社交**（语音视频/朋友圈/Space/内置游戏；红包仅本地演示）、**原生挖矿 V1/V2**、**5 平台工程产物**、**多因子认证**、**AA 五类账户与单笔/批量 UserOperation 路径**、**Aave/LI.FI/ETH-Lido 的执行代码**、**批量转账/CSV、观察钱包、Keystore、ENS、行情页**。其中涉及真实资产、付费 key 或尚未覆盖平台的部分必须保留验证限定；"功能最全面"、"AA 行业最完整"、"安全所有钱包最全面"等绝对表述不成立。

> **2026-07-14 校准（§15）**：H1 2026 的三条关键赛道是①原生稳定币/钱包卡/收益，② AI Agent 钱包，③ EIP-7702 主流化。N42 已补 Aave 稳定币 Earn 入口，但仍无原生稳定币、银行卡和 agentic 代执行；EIP-7702 属能力对齐，不再作为独有卖点。对比名单已补 Bitget Wallet / Binance Web3 Wallet / Exodus / Backpack。
