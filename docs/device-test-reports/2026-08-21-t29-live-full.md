均能恢复。独立入口 `lib/main_live.dart` 的失败原因是生产 homeserver 禁止匿名注册：

```text

```

独立入口目前不适用于生产环境；真实可用入口是主 App 的已认证 Chat 路径。

Android 最终重试使用当前源码重新构建的 788.3 MB Profile APK，传输完成后系统返回：

```text
Performing Push Install
Failure [INSTALL_FAILED_USER_RESTRICTED: Install canceled by user]
```

因此 Android 未进入 App 登录或直播代码，仍为设备侧 `BLOCKED`。

## 修复 1：生产 MatrixRTC 路由可用于直播

生产 `.well-known` 给出：

```json
{
  "org.matrix.msc4143.rtc_foci": [{
    "type": "livekit",
    "livekit_service_url": "https://m.si46.world/livekit/jwt"
  }]
}
```

实际部署状态：legacy `POST /livekit/jwt` 为 301，跳转后的路由为 404；官方
`/livekit/jwt/sfu/get` 存活。旧客户端只要传 `broadcaster/viewer` role 就强制走
legacy 路由，因而必然失败。

`3585fafa` 的处理：

- role 请求仍优先走可做发布限权的 legacy 协议；
- 只有 legacy 明确返回 301/308/404/405/410 时，才使用短期 Matrix OpenID 向
  官方 `/sfu/get` 换票；
- 401/403、网络异常和非法响应绝不回退，避免绕过授权或泄露长期 access token；
- POST 明确 401/403 后不再用旧 GET 协议重复发送长期 token。

双机日志分别出现 broadcaster/viewer 的官方换票成功，随后两端连接 LiveKit。
主播看到本机摄像头预览，观众看到主播画面，在线人数从 1 变为 2。

安全余项：官方 MatrixRTC 换票契约不接收本项目的自定义 role。客户端 viewer
不会主动发布，但“viewer token 服务端禁止 publish”仍需服务端结合 Matrix 房间权限
或扩展签发服务实现；报告不把该服务端能力冒充为已完成。

## 修复 2：预测事件不再被静默丢弃

真机首次建市时，Matrix 数据库已经存在合法 `pred/create` 事件，但主播按钮仍显示
“开预测”。根因是 JSON 解码后的选项为 `List<dynamic>`，`PredEvent.tryParse` 返回时
运行时强转 `List<String>` 抛错，又被解析边界静默捕获，导致所有端忽略建市事件。

`3585fafa` 在不可信输入边界显式转换为不可变 `List<String>`，并增加 JSON round-trip
跨设备回放测试。发送成功后还会先加入本地 pending 重放，Matrix 服务端回显后按
marketId 替换去重；发送失败不会产生假市场。

## 修复 3：同房间 Timeline 并发创建竞态

修完类型转换后，观众数据库能收到预测事件，但已在房内的预测卡片仍偶发不刷新。
直播页会同时启动弹幕、礼物和预测三个 `watchMessages`。原实现的 Timeline 缓存只缓存
完成结果，没有缓存进行中的 `room.getTimeline()`：三个订阅同时 miss 后创建三份
Timeline，最后一份覆盖缓存，早先订阅继续持有不再更新的旧对象。

`3585fafa` 为同一 room 增加 in-flight single-flight 复用，所有订阅共享同一个
Timeline 和更新源。真机重装后验证：观众在房内时创建新预测，7 秒内实时出现；主播
开奖后观众卡片实时切为“已开奖：是”。
