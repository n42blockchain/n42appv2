## 覆盖范围

- 首次加载等待 JavaScript channel 和存储配置完成；多标签进度、URL、标题、导航状态、书签读写及关闭后的迟到回调。
- 原生导航回调拒绝危险协议；剪贴板桥接的 WalletConnect URI 去重。
- 未连接来源不能读取账户，账户连接需要审批，后台请求保留原始来源，拒绝和未知方法返回对应 JSON-RPC 错误。
- 不同端口授权隔离；跳转、刷新、离开后返回或关闭标签后，旧授权结果和错误不能回调至新文档；同源 SPA 路由更新保留有效请求。
- 钱包模型数量不变但对象替换时，后续请求使用新模型。

测试在真实 BrowserProvider 上运行，将原生 WebView、数据库和钱包列表替换为内存实现。敏感签名请求停在拒绝审批分支，不取真实密钥、不发交易。JavaScript 仅检查发送内容，不执行真实 JS 引擎；原生 WebView 和真机行为仍需独立验收。

## 测试发现并修复

1. `_originOf` 丢弃端口，导致同主机不同端口共享账户授权。HTTP(S) 来源改用 `Uri.origin`。
2. 等待用户审批期间没有检查文档是否更换、标签是否关闭，旧结果会继续执行账户注入和 Promise 回调。增加文档版本及存活校验，并覆盖失败返回；完整页面加载与跨源 URL 变化会使旧请求失效，同源 SPA 路由更新不误取消。
3. DApp handler 缓存只比较钱包模型数量，数量相同的替换保留旧链/账户。改为比较实际模型列表。

旧代码的[授权隔离回归](authorization-before.log.gz)出现 3 项失败，对应前两个问题；[模型缓存回归](wallet-model-before.log.gz)出现 1 项失败，对应第三个问题。最终新增的 38 项测试全部通过。
