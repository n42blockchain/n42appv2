# 后续实施与验收：交易竞态和 receipt 状态

2026-10-10。此批修改 Flutter 钱包发送和 EVM 交易详情实际路径。

## 已实施

1. 发送页已有 gas 估算在途时拒绝再次启动确认，且只有本次估算明确成功才继续。
2. 地址解析、gas 等待和用户确认后重新核对金额、收款地址、备注、源地址、网络、coin type 和选中钱包。变更后丢弃本次确认，避免旧意图进入签名。
3. 详情查询使用递增请求代号，旧搜索响应与页面退出后的响应不能改变当前状态或重启定时器。
4. receipt 错误文本、抛异常、非法状态和不匹配的 transactionHash 不再被当成有效结果。暂时查询失败保留已经观察到的 receipt 并显示错误，不误判为重组。
5. 已返回 receipt 的交易仍每12秒查询；无 receipt 时每3秒查询。成功查询返回 null 时退回 Pending 并清除旧 blockHash；重新出现 receipt 时更新成功/失败和区块。轮询随页面退出取消。

## 验收与边界

真实生产 Widget + 受控异步响应验证：gas 在途阻断，金额/地址/备注/网络变化阻断，确认期间切网阻断；RPC 错误与异常恢复；receipt 消失/重入块；旧搜索响应；销毁后响应；非法/其他交易 receipt；错误响应不抹去既有 receipt。

此处“重组验收”指页面对 RPC receipt 变化的行为验证，不是对真实链共识最终性的验收。页面仍使用现有 Success/Failed/Pending 文案；Success 表示观察到 status=1 的 receipt，不代表 finalized。索引事件和余额同步、进程被杀后的付款恢复、未知广播结果的持久化幂等仍未关闭。12秒查询每个打开页面增加约5次RPC/分钟；未测真机耗电或确认页P95。

当前重复点击地址解析只进入一次确认/签名已有回归覆盖；跨页面、跨进程和广播响应丢失的重复付款不作通过声明。
