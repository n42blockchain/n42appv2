# N42Chat 周报建议：实施与验收计划

日期：2026-10-10。执行顺序：P0 恢复与弱网 → P1 AI 授权 → P2 可验证回执。代码在独立 `n42_chat` 仓库维护，宿主通过 Git SHA 固定依赖；不修改 `packages/n42_chat` 缓存镜像。

## 范围与当前判断

周报中的恢复反馈、文字与媒体独立发送、逐条 AI 选择授权、EVM 精确回执检查已有实现。本轮复核和补缺，不重复建设。竞争产品的公告是设计参考，不是 N42 的验收证据。家长控制、桌面回声消除、文件协作等不属于本轮三个优先级。

| 阶段 | 实施项目 | 验收证据与通过条件 |
| --- | --- | --- |
| P0 | 保持 Matrix 加密失败关闭；恢复结果显示账号、服务器、总密钥数、成功数和失败数；保留重试入口。文字 busy 与并发媒体计数分开。 | 恢复失败不报成功；多个上传任一结束不能清空其余 busy；上传保持未完成时文字仍调用真实发送仓库。对应恢复反馈、ChatBloc 行为测试。密钥数不等于可读消息数。 |
| P1 | 摘要与快捷回复只发送用户本次选择且未改变的文本；授权绑定账号/client/room。增加两分钟单调时钟期限，关闭快捷回复撤销授权，重复刷新不创建并行请求。回包重新检查选中消息，切换账号后不显示旧错误。 | 默认不选、取消不授权、只返回选中 IDs；精确到两分钟边界失效；撤销不可恢复；正常新授权有效；真实 helper 与 widget 测试通过，完整包可编译。已经发送给供应商的数据不能撤回。 |
| P2 | 复核现有转账状态与 EVM 收据检查；提交哈希只表示已广播，确认依赖匹配的链、资产、地址、精确金额、确认数和规范区块。 | 入站聊天消息不能自行声明支付完成；receipt mismatch、失败、确认不足、被重组移除必须不确认；宿主 RPC fixture 测试与转账仓库测试通过。 |
| 集成 | 发布可获取的 Chat 源码 SHA，宿主 pubspec 与 lock 同时固定该 SHA，运行宿主初始化与钱包桥测试。 | resolved-ref 与固定 SHA 一致；相关宿主行为测试通过；记录本地提交与发布状态，避免把源码变更当成安装版本生效。 |

## 外部验收步骤（按用户要求跳过配置步骤，本轮不判通过）

1. 创建只含测试内容的加密房间；记录已知文本 event IDs 和附件明文哈希。两手机与电脑分别执行换机、退出重登、密钥恢复；逐设备记录预期、可读、缺失、附件完整与失败数。丢失且无任何备份的密钥不能重建。
2. 限速、断网、后台恢复：保持大附件上传，发送短文字和回执，记录送达 P50/P95、失败率和恢复耗时；校验无重复文本、无明文媒体回退。当前加密附件仍有 50 MiB 内存上限。
3. 使用隔离 AI 服务检查实际请求日志仅含选择文本和必要角色；过期、切换账号、编辑/删除选中消息与关闭面板后不显示旧结果。群机器人尚无完整服务，不把客户端授权窗口描述成机器人服务端访问控制。
4. 独立收款设备在测试网络检查原始交易与收据，验证相同交易的重放、链切换、确认不足和重组。当前是打开验证页时的即时检查，不是持续结算保证。

## 保留的工程缺口

- 完整付款—交付—确认关系、持久幂等记录和权威结算不是现有哈希卡片；需要独立业务协议与状态存储后再验收。
- 群 AI 的身份、移除后的服务端撤权和 webhook 幂等执行仍缺服务实现；不借本轮客户端摘要功能声称完成。
- 随机盐摘要承诺不上链：没有选定链、合约、签名验证协议和明确披露。聊天内容及社交关系继续不上链。
- 新授权说明沿用已有英文回退；全语言翻译仍属于现有本地化待办。
