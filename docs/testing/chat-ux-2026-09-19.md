# Chat, contacts and account switching — 2026-09-19

## Scope and reference patterns

The user approved a full interaction pass on chat, contacts and account switching. Wallet navigation and transaction flows remain outside this scope. Reference patterns are adapted to N42's existing design tokens and encrypted Matrix account model:

- [WhatsApp navigation and chat organization](https://www.meta.com/design-at-meta/blog/whatsapp-user-interface-update/): clear navigation, filters and accessible attachments.
- [Signal message requests](https://support.signal.org/hc/en-us/articles/360007459591-Signal-Profiles-and-Message-Requests): preview identity, distinguish pending requests from accepted contacts.
- [Discord call re-entry](https://support.discord.com/hc/en-us/articles/360042693171-Mobile-Voice-Overlay-Android): a persistent way back into a minimized call. N42's banner stays inside the app.
- [MetaMask account selector](https://support.metamask.io/configure/accounts/switching-accounts-in-metamask/): make the active identity visible and account selection explicit. Chat and wallet accounts are not merged.

## Implemented behavior

| Area | Result |
| --- | --- |
| Chat list | All / Unread / Groups filters; muted unread chats remain in Unread; pinned ordering retained; lazy list rows; filtered-empty recovery; initial-load retry; refresh waits for completion. |
| Account entry | Chat header opens the selector and shows the current Matrix ID; host Back action remains available on phone and split layouts. |
| Account selector | Current-account label, switching state, serialized actions, persistent failure/re-authentication guidance, and add-account action. UI switching is blocked during an active call. |
| Account isolation | Chat and profile roots are keyed by user ID, so successful account changes recreate page state. Independent SDK databases and logout revocation remain intact. |
| Search to contact | Search results open a profile for identity/relationship review instead of creating and entering a pending room. |
| Contact relationship | Incoming requests link to New Friends; outgoing requests display Request sent and disable repeated submission. Standalone profiles load relationship state and offer retry on failure. |
| New Friends | Separate received/sent sections, readable identity cards, wrapped actions, busy feedback, and immediate removal after confirmed acceptance/rejection while refresh completes. |
| Contact search | Direct clear action and an input that can grow with text size. Existing contact-to-profile navigation and saved details remain in use. |
| Messages | Larger retry touch target. Unreadable encrypted messages explain device unavailability and open recovery options; they do not promise missing keys can be recovered. Delivery indicators expose text semantics. |
| Attachments | Responsive, vertically scrollable grids within horizontal pages; multiline labels, press feedback, and disabled accessibility state for unavailable callbacks. All prior entries remain accessible. |
| Calls | A themed Return to call banner reuses the active-call manager. No separate call or extra call record is created by returning. |
| Dynamic text | Story-bar height adapts to enlarged text; account/request/message layouts checked in light and dark themes. |

## Acceptance and release boundaries

- This task does not upload TestFlight or produce an APK. Build 2026072692 predates this UI pass.
- On both feedback phones, verify search → profile → request → acceptance → messaging, switch both accounts without logout, restart the app, and check current identity, incoming messages, call return/hangup and a single call record.
- Previously missing encryption keys remain unrecoverable without another valid key source. Changing placeholder wording does not repair key loss.
