## 本轮确认并修复的问题

### 1. 朋友圈受限可见范围（高）

- 文本、图片、视频发布均遗漏了已选择的好友 ID；现在完整传递名单。
- 原先受限动态仍发布到所有好友共用的房间，客户端隐藏无法阻止其他成员读取底层事件。新受限动态改用独立邀请制房间，按已确认的私聊好友生成接收名单；只有发布者可以邀请、修改状态和发布动态。
- “仅自己”“部分可见”“不给谁看”采用发布时的固定名单。邀请失败、名单不可用或切换账号时阻止发布。
- 解除某好友的全局限制不会把他加入原本不包含他的旧受限动态。
- 个人朋友圈聚合读取多个房间，删除按动态实际所在房间执行；删除失败向上层报告。

### 2. 自动加入朋友圈缺少好友校验（高）

原先房间邀请的 reason／名称就能触发自动加入并回邀。现在必须确认房间创建者与当前用户已有双方加入的私聊；陌生人、待同意的申请不能通过这条路径获得回邀。

### 3. 视频列表旧请求覆盖新权限（中）

旧请求可能在权限更新后返回，把已移除内容重新显示。现在为每次请求编号并丢弃过期结果；权限更新、监听错误会清理当前结果。视频组件按动态 ID 绑定，避免列表变化时复用其他视频的播放器。

### 4. 相册与资料编辑的异步边界（中）

- 选择媒体期间防止重复打开选择器；页面退出后忽略迟到结果；读取异常显示反馈。
- 取消图片编辑时保留原有视频草稿。
- 读取好友资料后再次核对账号，防止切换账号后显示旧资料。
- 电话／备忘输入框随对话框实际销毁而释放控制器，取消固定延时释放。
- 照片复制到一半失败时删除未完成文件，避免产生孤立文件。
- 修复好友可见范围选择页 ListTile 缺少 Material 容器的问题。

### 5. 直播重复进入保留旧路由（中）

原先整个应用共用一个直播 GoRouter，重新打开可能保留之前的子页面。现在每个 LiveApp 拥有并释放自己的路由器，普通入口进入直播首页，开播入口直接进入开播页。

- 本轮源码修复需要新安装包；既有 TestFlight／Android **2026072670 不包含这些修复**。
