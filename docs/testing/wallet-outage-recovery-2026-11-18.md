# N42 钱包断服恢复演练

2026 年 11 月 18 日，在本机 Anvil（链 ID 31337）上使用临时账户与测试资金。分别验证恢复材料、签名会话、RPC 和到账。测试未向公共链广播。

## 可用的恢复路径

| 用户持有的材料或状态 | 断服时可采取的操作 | 演练结果 |
| --- | --- | --- |
| 助记词及原账户使用的附加口令 | 用支持原网络、派生路径和账户索引的兼容钱包恢复，校对原地址。 | WalletCore 的有口令和无口令样本都恢复到原地址。省略原本设置的附加口令会派生出不同地址。Dart 钱包发送器的无口令演练也通过。 |
| 原私钥 | 在兼容钱包本地导入并校对原地址。 | WalletCore 恢复原地址。Dart 钱包发送器的独立演练也通过。 |
| 加密 Keystore 与密码 | 在支持该格式的钱包本地解密导入并校对原地址。 | WalletCore 恢复原地址，拒绝错误密码。 |
| Web3Auth 签名会话仍已加载 | 保留原设备的可签会话。如原地址仍能签名，可走匹配原链的可用 RPC。 | 对提供商平台通道注入故障后，N42 的 Web3Auth 封装仍能用已加载的签名材料完成一次转账，尝试调用提供商次数为 0。 |
| 只有社交登录，且冷启动拿不到签名材料 | 保留仍能签名的设备和已有恢复材料。在供应商侧恢复访问后再次校对原地址。 | 冷实例无法签名，也没有新增广播。当前没有经本次演练验证的离线退出路径。供应商的实际恢复受 SDK、网络与登录方式约束。 [Web3Auth 恢复说明](https://builder.metamask.io/t/web3auth-embedded-wallets-service-restored-what-you-need-to-know/3690) |

恢复原地址后，选择指向**原网络**的可信备用 RPC，核对链 ID、地址和可付手续费。先发一笔小额交易，确认成功回执和收款余额，再继续操作。仅在钱包或离线工具本地输入恢复材料。

## 验收证据

- 原生路径使用 N42 的 iOS WalletCore 依赖，在新建模拟器内运行独立测试程序。默认 RPC 返回 HTTP 503。四个账户分别通过助记词、助记词与附加口令、私钥和加密 Keystore 恢复，并通过备用 RPC 各广播 **1,000,000 wei**。四个 EIP-1559 成功回执的发件人、收件人、手续费与前后余额均已核对。密钥、助记词和密码只在测试进程内生成和使用。
- N42 iOS 应用的助记词、私钥导入与原生存储两项测试均通过。复跑启用 `N42_WALLET_OUTAGE_QA=true`，阻断应用测试中的非回环 HTTP 连接。助记词用例有 7 次外部连接被阻断，私钥用例为 0 次。测试使用隔离宿主状态，日志仍有测试中未初始化全局钱包列表通知器的提示。
- 应用路径使用实际 `EvmSender`。默认 RPC 返回 503 时，助记词和私钥路径都在签名前停止。切换备用 RPC 后两笔到账；第三笔由已加载的 Web3Auth 会话发出。冷会话被拒绝，发送者 nonce 和收款余额确认没有额外转账。测试 HTTP 连接限制在回环地址，外部连接尝试数为 0。
- 演练复现地址前缀造成的误判。Web3Auth 地址可无 `0x`，确认中的同一地址可能带前缀。发送器改为比较解析后的 EVM 地址。不同地址仍会在签名前被拒绝。发送回归 **79 项**通过，回环演练与 Web3Auth 套件 **24 项**通过。改动范围的静态分析无错误或警告，有一条已有的 info。

私有测试日志、原生样本源文件和 SHA-256 清单保存在 `~/.config/n42/qa/wallet-outage-20261118.Z0308l/`。模拟器已关机。

## 适用边界

直接链上转账已使用隔离链验证。应用内导入与备用 RPC 到账是两组独立实验。正式发布版在注销或换机后能否进入本地恢复页、真实供应商停运、物理设备和公共链仍需要各自的证据。其他链、代币、硬件钱包和智能账户未纳入本轮。
