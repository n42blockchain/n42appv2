# Chat 更新深度审计与修复

范围：上一轮Chat新增代码（Mini App/OAuth/桥、附件上传下载、Markdown、NFC、遥测）及宿主接入。基线为宿主`66f5d8147`、Chat功能源码`61d32227`。发布使用修复后的Chat `699062eedfe5d3a67cf33f0e84b9c7e2cccb9ac4`，安全SDK版本`1.1.1`。

## 已修复问题

| 问题 | 修复与回归证据 |
| --- | --- |
| 上传期间切换账号或房间加密状态，旧流程仍可能发布附件 | 在首个异步等待前捕获账号会话；发布或明文回退前重检。文件、图片、视频各覆盖账号和加密变化，共6项新用例。 |
| 下载取消后立即重试，旧任务可能污染新任务状态 | 同一任务的旧执行完成清理后才重启；独立记录取消标记，迟到响应不能落盘或改变新状态；释放服务时完成等待者的取消通知。 |
| 两次读取之间密文变化，首轮哈希不足以保证实际解密内容 | 第一轮有字节/取消边界；第二轮对实际解密字节再次校验哈希，失败删除临时明文；密钥在异常路径同样清理。 |
| 签名链接在等待nonce存储后可能已过期 | 返回目标前重新验证有效期；安全SDK升为1.1.1，支持策略区分修复版本。 |
| NFC旧读取尚未返回时，新扫描被全局读取标记阻塞 | 读取状态限定在单个会话，旧回调不能阻塞新会话。 |
| Markdown图片超时后重试使用已关闭连接 | 每次请求新建传输，超时/结束关闭本次连接。 |
| 文档预览具有同样的超时重试问题 | 同样改为每次请求独立传输；保留HTTPS、大小、无重定向和加密校验限制。 |
| 外部链接打开失败产生未处理异步异常 | 捕获启动失败并给出可见错误，不报告已打开。 |
| 成功的void解密被遥测记成null失败 | 显式区分void成功与需要返回URI/事件ID的操作；原有null上传仍计失败。 |

URL原始解析、重复/编码参数、主框架OAuth回跳、桥nonce/权限及签名策略路径已复核，并纳入完整回归。没有因本次审计放宽原有安全限制。针对性修复回归57项通过；预览/遥测组合121项通过，两组存在重叠，不累加。

## 发布验证

正式上传前要求完整Chat回归、宿主集成回归、静态分析、主应用/通知扩展版本一致、分发签名与NFC entitlement/profile一致。最终测试计数、IPA校验值、上传回执和Apple处理状态写入本次`docs/releases/`发布记录。

实机NFC、大文件真实双端收发、生产策略部署和商户试点仍沿用Chat `OPEN_ISSUES.md`中的验收边界；上传TestFlight不代表这些项目已经通过。本轮不调整服务器配额，不发布商户后台。
