## Finding

1. **A failed repeat run leaves a stale success receipt.** `scripts/walletcore_android_preflight.py:202-227` verifies inputs and writes `--receipt` only after success, but does not remove/invalidate an earlier receipt before starting or on the exception path. Sequence: run successfully to create `final-preflight.json` with `passed: true`; mutate a source/tool/header/native input; rerun against the same receipt path; the command exits 1 but the prior success receipt remains. A later build or evidence collector that checks the receipt file can mistake old verification for current inputs. The four mutation tests call individual verifier functions and do not test this repeated-run case. Clear the receipt before validation or use an atomic per-run receipt with a verified run identity, and add a pass-then-tamper negative control that confirms no accepted success receipt survives the failing run. This is a gate integrity issue; the retained successful normal and `-O` runs remain valid point-in-time observations.
