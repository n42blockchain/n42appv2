## Finding

**Pinned-path verification is separated from the bytes actually packaged.** `scripts/build_walletcore_maven.py:34-42,130-204` calls `verified_file`, which hashes each input path, then later reopens the same paths to parse module metadata, read the strip manifests, read JNI replacements, open the official AAR and copy POM/source/proto files. A file replacement between those operations can make the maintained repository consume different bytes from the hardcoded pinned SHA-256; the final report computes output hashes but does not require them to match the official input pins or an expected candidate output. This is the same hash-then-read class of defect previously fixed in the link environment recipe. Bind each official artifact, manifest and stripped JNI member to one checked byte buffer (or immutable opened handle), then parse, repackage and write from those exact checked bytes. A deterministic swap-between-validation-and-use control should fail before output is accepted. This is a recipe guard fix; the already produced AAR can be compared against the corrected recipe without relinking or repeating Gradle selection if bytes remain identical.
