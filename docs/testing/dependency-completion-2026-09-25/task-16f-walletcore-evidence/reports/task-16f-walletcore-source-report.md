Its `tools/rust-bindgen android` builds four target archives, then runs cbindgen and `codegen-v2` Cargo; generation also runs `codegen/bin/coins`, Ruby `codegen/bin/codegen`, comment conversion, Java/C++ protobuf and both custom plugins, including a Swift typealias output. ## Review fix: reject stale success receipt

The independent review in `task-16f-walletcore-source-review.md` found that a second failed `--receipt` run retained the first run's `passed: true` file. The command-level regression first reproduced this failure (`receipt-red.log`: one test failed because the receipt still existed). The fix invalidates an existing prior success receipt before checking any source/tool bytes. It refuses a symlink, a receipt path equal to one of the input manifests, or a path inside the source, Boost-header or official-artifact input trees. It also refuses to remove an unrelated existing file. A failed repeated validation now leaves no accepted success receipt. This is a gate-lifecycle fix; the Wallet Core source and tool bytes did not change.
