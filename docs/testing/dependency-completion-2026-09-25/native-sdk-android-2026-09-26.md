## Old packaged behavior and current consumer

The original packaged AAR was run with the same synthetic deposit/exit/fee inputs on the strict16KB fixture. Old and maintained exit and fee-call JSON are byte-identical. Deposit `to`, `value` and all ABI calldata are identical. Supplier v0.2.2 adds only `gas: "0x493e0"` (300,000) to deposit JSON; tagged source `crates/n42/mobile-sdk/src/deposit_exit.rs:94-96` sets that field explicitly, while the old AAR omitted it. Thus the SDK outputs are **not** byte-identical. `tools/android_native_smoke/compare_mobile_sdk_vectors.py` passes on the old/new raw fixture logs and fails on a deliberately changed-gas control.

Current V2 Dart route is `MiningApi` → `MiningChannel('trustdart')` → native `MiningHandler` → `MiningV2Provider.createDepositUnsignedTx` (`lib/features/mining_v2/provider/mining_v2_provider_actions.dart:279-287`) → `MiningWeb3._buildTransaction` (`lib/features/mining_v2/api/mining_web3.dart:48-56`). That builder reads only `to`, `value` and `data`, fetches gas price independently and uses its existing `maxGas=6000000`; it ignores the newly added SDK `gas` field. No Dart caller of the alternate plugin deposit method was found under `lib/`. The supplier field was retained. `_buildTransaction` directly calls the RPC-backed `getGasPrice()`, so no live submission/fee estimate or new production test seam was used to assert an end-to-end transaction.

## Advisory and acceptance limits

The repaired lock's selected Android normal/build graph has 633 package pairs and intersects the recorded advisory database with 0 vulnerability and 0 unsound records. It still contains seven unmaintained warnings (`bincode`, `core2`, `derivative`, `fxhash`, `instant`, `paste`, `proc-macro-error2`); `core2` is also yanked and `proc-macro-error2` has a future-compatibility warning. The **whole workspace lock** audit exits 1 with nine vulnerability records in other workspace/dev graph paths. This graph scan cannot prove vulnerability absence from every opaque binary or the current iOS package. The current iOS SDK was not rebuilt here; its shared Rust dependency follow-up remains separate.

No valid supplier `UnverifiedBlock` golden fixture was established for a successful `genBlockVerifyResult`; JNI export presence and compilation do not prove block verification. The BLS oracle establishes keypair/signature behavior only. Production Rust WSS transport was not run, since invoking `runClient` would start validator work; the fixture-only certificate decisions and same-library initialization do not prove an end-to-end production WSS handshake. Whole-app native alignment, production signing and store acceptance remain open. Source license declarations and corresponding-source inputs are documented in the checked-in rebuild recipe; no combined app license conclusion is made.
