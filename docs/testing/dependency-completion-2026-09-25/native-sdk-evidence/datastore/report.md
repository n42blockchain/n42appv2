## One-APK device fixture

Synthetic fixture source and runner are under this ignored task workspace, archived separately in `docs/testing/dependency-completion-2026-09-25/native-sdk-evidence/datastore/`. A pinned Flutter 3.47.5 debug APK targeting SDK37 was built once; APK SHA256 `0ecb6bf189267a334236d877904bc7ea5e08bf324ede04dd2005b1c289964404`. The dedicated emulator-5560 had 16384-byte pages, arm64-v8a, airplane mode on, no external route, linker compatibility `fatal`, and package compatibility disabled `true`, before and after the run. No app account, wallet, network validator, or production data was used.

The fixture called actual `SharedPreferences` legacy APIs and explicit `SharedPreferencesAsyncAndroidOptions(backend: DataStore)` for bool/int/double/string/string-list, key enumeration, remove, and clear. It also called actual `MultiProcessDataStoreFactory` with a synthetic integer serializer so DataStore's shared-counter JNI is exercised. One installed APK was launched with `seed`, force-stopped, and relaunched with `verify`; both phases returned PASS. Legacy and DataStore values survived the process restart. The synthetic persisted counter advanced 0→1→2 through `MultiProcessDataStore`; its internal native shared-counter path was exercised, with distinct PIDs 12521 and 12620. The package loader resolved `base.apk!/lib/arm64-v8a/libdatastore_shared_counter.so`; its executable map offset `0x01450000` equals the ZIP local-entry data offset, accounting for name and extra fields. The packaged member SHA256 `178f89a2c6c9234ddf980dd4cd1f3616186a46b2b932aafa6707abd04c5fd76a` equals pinned-NDK `llvm-strip --strip-unneeded` output from the AAR arm64 member. `SharedCounter$Factory` AAR bytecode shows Android library load and native truncate/create calls; on Dalvik a failed load throws. Exact result, verifier output, build log, APK badging, bytecode, and dependency graph are archived. Wrong AAR SHA and +4096 map-offset controls both exited 1 (`negative-*.log`).
