# Task16B offline BLS keypair check

The selected packaged Android MobileSdk AAR (`ec2dce904f925ca044089164e6b7e7821ded77788c214676a18ed357f27e87a5`) exposes `Api.generateBls12381Keypair()`. Tagged source `crates/n42/mobile-sdk/src/blst_utils.rs` uses `blst::min_pk::SecretKey::key_gen` and returns JSON of `sk.to_bytes()` then `sk.sk_to_pk().to_bytes()`, both hex encoded. This check uses a separate test-only JNI cdylib from `tools/android_native_smoke/bls_oracle/`, pinned `blst 0.3.15` and `jni 0.21.1`, lock SHA-256 `59a80fbfe33fe036a464c0fe8478d7cf84789a5bd058b40069c9905cb100ddcb`.

The Flutter harness calls the **packaged SDK** API, passes the pair in process to the separate oracle and receives only a Boolean. The oracle decodes the secret with `SecretKey::from_bytes`, derives and compares the public key, signs fixed test bytes under a test domain, accepts that signature for the original message, and rejects it for a changed message. The random fixture secret and public key are never logged, persisted or used for a wallet/validator/network request. The oracle source and binary are never part of the production app or production MobileSdk AAR.

Recorded build: Rust 1.97.1, cargo-ndk 4.1.2, NDK 28.2.13676358, arm64-v8a API23, `-z max-page-size=16384` and `-z common-page-size=16384`, `--release --locked --offline`. Android oracle binary SHA-256 `1fb890c469294e71be965684cddc9168ffd2f19d7946607cd26d95c9d2c08a6d`. `rust-sdk-rebuild/bls-oracle-build-final.log` records final build; `bls-oracle-elf-audit.json` checks its one LOAD/GNU_RELRO library 1/1. `cargo +1.97.1 test --locked --offline` checks matching/mismatched pair and invalid hex 1/1 in `bls-oracle-host-test.log`.

On disposable `emulator-5560` (`PAGE_SIZE=16384`, linker compatibility `fatal`, package compatibility disabled), `N42_SMOKE_BLS_ORACLE_JNILIBS` supplied only the fixture library and `N42_SMOKE_MOBILE_AAR` selected the tracked maintained AAR. `flutter test integration_test/native_mobile_sdk_bls_oracle_test.dart -d emulator-5560` with pinned Flutter 3.47.5 passed 1/1 in `rust-sdk-rebuild/bls-oracle-runtime-final.log`. The test returns true only after all positive and negative BLS checks pass. This establishes the emitted pair relationship and offline signature behavior; it does not provide a valid `UnverifiedBlock` for `genBlockVerifyResult` or run a validator.
