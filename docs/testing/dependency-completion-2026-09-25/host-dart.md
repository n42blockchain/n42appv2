# Task 14A host Dart dependency integration

## Source and solver decisions

- The host resolves Chat from reviewed Git commit `e71e59ea3ab33fa0c0681baebe4ab38ece019014`. The direct secure-storage dependency and the root overrides resolve reviewed app Git commit `9733aa21eb7e4fa98c2aa8a287ef9588960023c2` for secure storage 11.2.0 and maintained Facebook desktop. These are immutable Git refs in `pubspec.lock`. Root `pubspec_overrides.yaml` repeats the overrides because pub replaces the manifest override map with that file.
- Reown 1.5.1 remains the unmodified official package. Its manifest caps secure storage below 11 and package_info_plus below 10. The host's narrow overrides are justified by the actual Reown call sites: its package identity helper only awaits `PackageInfo.fromPlatform().packageName`, which is covered by a focused test, and its secure store/keychain are replaced before SDK initialization. Remove the overrides when official Reown accepts these major versions and preserves the same fail-closed security behavior.
- Official fl_chart 1.2.0 caps Equatable 2 and uses the removed `EquatableMixin` in nine runtime files. `packages/fl_chart` retains the MIT licensed published runtime and replaces that mixin with Equatable 3's `Equatable`; `packages/fl_chart/N42_PROVENANCE.md`, `UPSTREAM_FILES_SHA256.json`, and `N42_PATCH.diff.gz` record the upstream archive hash, every pristine retained file, and the narrow upstream-relative patch. Bar, line and pie equality, changed-value and rendering tests cover the migrated APIs. Remove the path source when official fl_chart supports Equatable 3 and these regressions pass.
- Official simple_html_css 5.0.0 caps XML 6. `packages/simple_html_css` retains the Apache 2.0 licensed runtime unchanged and updates only the XML constraint to 7. `packages/simple_html_css/N42_PROVENANCE.md` and its hash manifest/patch provide the same source audit. HTML style, entity, link, malformed and prefixed-tag tests, plus the app's RSS namespace tests, exercise XML 7. Remove the path source when official simple_html_css supports XML 7 with equivalent behavior.
- Freezed 4.0.2 requires analyzer 14, while the latest stable intl_utils 2.8.16 requires analyzer 13. Freezed 4.0.1 is the newest stable version whose analyzer constraint includes 13; build_runner 2.16.1, json_serializable 6.14.1 and mockito 5.8.1 also resolve with analyzer 13. Remove the exact 4.0.1 cap when intl_utils supports analyzer 14. No analyzer override is used.

The two maintained package inventories match every recorded upstream file hash (66 fl_chart files, 7 simple_html_css files). Both compressed patches pass gzip integrity and upstream-source dry-run patch checks. Optional upstream READMEs are omitted. The one pristine fl_chart runtime file using CRLF is marked `whitespace=cr-at-eol` in `.gitattributes`; staged `git diff --check` still passes without rewriting that source.

## Host behavior

- Wallet and sensitive preference stores use the reviewed v11 Android namespaces `n42_secure_v11_wallet` and `n42_secure_v11_preferences`, with logical prefixes `n42_` and `sp_`, and `resetOnError: false`. Existing iOS Keychain accounts and accessibility stay intact. The reviewed native adapter migrates legacy values before opening these namespaces.
- `N42ReownSecureStore` restores only `wc@2:core:` JSON objects from encrypted storage, validates the keychain's string values and metadata, and rejects malformed data without deleting it or falling back to shared preferences. Its writes persist before changing its in-memory map; any storage failure makes the instance unusable. `N42ReownKeychain` preserves Reown's `0.3//keychain` format, serializes writes, and broadcasts only after persistence. A failed key write poisons that keychain until a fresh core is constructed.
- The host injects both fields into an official `ReownCore` and wires a keychain failure callback before `ReownWalletKit.init`; it assigns `signClient` only after init succeeds. A failed active key write or delete disconnects and discards only the client that owns the failed keychain, so a stale instance cannot clear a newer one. Upstream `Pairing.pair` awaits `pairings.set(topic)`, then `crypto.setSymKey`, then relay `subscribe`. On a pairing key write failure, the host retains the local client reference for recovery. For a newly inserted pairing, it re-reads encrypted storage with a fresh store and deletes only that exact nonsecret pairing record when the durable key is absent. Existing pairing records and uncertain durable reads are preserved. A process crash between upstream pairing metadata write and the key write can leave an orphan pairing for upstream startup behavior; no speculative startup deletion is performed.
- FilePicker 13 call sites now use `pickFile`'s `PlatformFile?` result, and the app adds Material UI delegates required by Pro Image Editor 14. Awaited returns in try blocks now allow asynchronous failures to reach their intended catch blocks. The device-only SQLite bootstrap using removed sqlite3 2/open APIs was removed.
- The sqlite3 3.6 hook uses Android's system `libsqlcipher.so`, iOS executable symbols, and a SQLCipher default for other hosts. The hook's package source confirms per-target `source` and `name` maps and the `system`/`executable`/`sqlcipher` choices. Android and Apple binary linkage are verified in Tasks 14B and 14C.
