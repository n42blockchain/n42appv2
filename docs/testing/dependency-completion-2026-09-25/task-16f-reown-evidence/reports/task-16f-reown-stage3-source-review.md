The runner records `git_head` at `:125` and current `SOURCE_FILES` hashes at `:126`, but `verify()` only recomputes current source hashes and never checks the reviewed commit or the source that produced the APKs. Pin or otherwise independently attest the three already-built APK SHA256 values (`4002e6ce...`, `efde15a5...`, `4ee64642...`) and exact reviewed/build source identity before install, and add substitution rejection tests. 2. **Bind packaged JNA JNI to the pinned JNA input through its build transform.** `verify_reown_wcpay_fixture.py:165–179` pins the JNA AAR SHA256 and requires the three APK JNA members to agree with each other, but never compares their bytes or a verified transform result with that pinned AAR. A common substituted JNA library could therefore pass. The original pinned AAR's ARM64 `jni/arm64-v8a/libjnidispatch.so` is SHA256 `abc26e994517bcaa3309acdb0a27373864086c7569c89d3087b8626fada9ef06` (176,520 bytes). The baseline compile log executes `mergeReleaseNativeLibs` and `stripReleaseDebugSymbols`. Thus requiring byte equality between the APK and original AAR would be wrong; pin the **packaged stripped** hash and retain the merge/strip derivation proof or an equivalent reproducible transform check. Add a wrong-common-JNA rejection test.
