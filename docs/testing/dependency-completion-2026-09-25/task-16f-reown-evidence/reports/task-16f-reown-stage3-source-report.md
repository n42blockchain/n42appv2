## Bounded calls and inputs

`tools/android_native_smoke/reown_wcpay_fixture/` has no INTERNET permission and takes one exact AAR file for baseline/candidate. It uses the same cached Android JNA 5.17.0 AAR in both variants (SHA256 `4dbeffffa665d97ad5aa7eee297531d3c841a86716ab7f774fd6956422b3cf38`) plus coroutines 1.7.1. Kotlin invokes the actual generated `uniffiEnsureInitialized` checker, then only malformed constructor JSON, missing-auth synthetic configuration, and malformed options/actions/confirm JSON. The valid synthetic configuration has `base_url=http://127.0.0.1:9` and placeholder app ID, but no valid payment link, account, request or network permission exists in the fixture. Tagged source `crates/yttrium/src/pay/json.rs:245-334` parses these requests before client methods, and `pay/mod.rs:951-975` validates missing authentication before lazy networking.

`scripts/prepare_reown_wcpay_fixture.py` checks the original release generated Kotlin hashes (`92458f5d...`, `5bf20f4f...`) and maintained AAR hash (`edf6908e...`) before writing. It changes exactly the expected logger checksum constant `32546` to `32547` in a task-local copy of `yttrium.kt`; the companion generated file is byte-identical and ARM64 JNI is the exact candidate hash `a89f233e...`. Preparation receipt: `task-16f-reown-stage3-build/mismatch-input/preparation.json`. Mismatch APK compiles these two generated files instead of the AAR classes, with the identical candidate JNI and JNA artifact. The runtime checker must reject it with `UniFFI API checksum mismatch` before any JSON operation.

The runner is fixed to `emulator-5560` and records strict/offline state (`PAGE_SIZE=16384`, linker `fatal`, package compatibility disabled, airplane mode enabled, empty route) before/after each fresh process and at completion. It binds each local/installed APK SHA, exact package, class-loader member path, PID, nonce, ZIP data offset and executable ELF maps; it checks both WCPay and JNA ARM64 members. It requires typed errors for the candidate and an actual UniFFI checksum rejection for the mismatch control. Official baseline PASS or recorded FAIL is preserved without inferring a crash from its static ELF audit. A missing process result fails the runner and keeps its partial receipt. Runtime evidence will be produced only after source review.
