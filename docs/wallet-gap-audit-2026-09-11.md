# 前序任务遗漏复核与补齐（2026-09-11）

本轮按实际代码与各批次验收记录交叉核对。首页改版之后仍有时间提示、异常处理、部分报价和加载布局的遗漏，已补代码与回归测试。旧报告保留当时结果；下面区分已补实现、已做验收和尚未交付的能力，不把静态入口引用当作功能闭环。

后续进展：聚合稳定币详情、普通稳定币的分网络入口、只读收款／网络跳转及余额状态已在[下一批补齐](wallet-aggregate-followup-2026-09-11.md)。本文的测试数字及“尚未交付”描述保留本批完成时的历史状态；最新聚合验收以该后续报告为准。

## 本轮修复

| 遗漏 | 修复后的行为 | 回归证据 |
|---|---|---|
| 首页停留时“刚刚更新”依赖父组件重建 | 独立时间文字在分钟／小时边界更新；后台及 TickerMode 隐藏时暂停，恢复立即校正；不请求行情、不重建资产列表 | 时间推进、暂停恢复、隐藏恢复、替换成功时间戳 |
| 定时任务异常通过 unawaited Future 逸出 | 资格检查与请求异常统一进入 Flutter 错误报告；解除进行中标记，下一次仍按五分钟重试；销毁后不能重启 | 请求异常、资格检查异常、在途销毁、晚完成、禁止重启 |
| 部分行情返回被标记为所有价格已更新 | 合并有效报价并保留缺失币种的旧值；不推进整组成功时间；区分部分行情、缓存和不可用提示；自动请求仍遵守缓存间隔，手动可重试 | 部分返回、无关币种、请求中变更币种、手动绕过缓存 |
| 行情币种键空格导致“有数据但匹配不到” | 缓存键统一 trim + 小写，匹配实际币种 unit 或 miniName | 带空格／大写的 BTC 报价正确更新估值 |
| 系统时钟回拨使稳定币缓存长期有效 | 与普通行情一致，负缓存年龄视为过期 | 回拨后重新请求并应用新稳定币报价 |
| 初次加载仍用旧行尺寸 | 骨架屏图标、内边距、尾部占位与紧凑列表一致 | 390 宽下与实际币种行等高；原窄屏大字号测试继续保留 |

## 最终验收

- 全量套件 **3,971 项全部通过，7 分 26 秒**，比上一批新增 13 项。完整 LCOV 为 **24,143/121,822 行（19.82%）**，前值 19.73%；仍未达到 70%。[全量报告](testing/coverage-gap-audit-full-2026-09-11.md)。
- 全量套件中的首页范围为 770/998（77.15%）、刷新范围为 379/627（60.45%）；独立模块测试集不同，应分别阅读。
- 小米安全导航 78 秒通过，iPhone 13 Pro Max 66 秒通过。均完成真实首页币种详情往返、手动刷新、部分行情文案断言及侧栏检查；不包含已排除的登录 Chat，不提交交易。
- 两端本次真实行情均返回不完整，因此正确保留整组成功时间并显示“部分行情”；这轮设备结果不宣称全部币种实时行情正常。独立只读接口复核 HTTP 200，68 个请求符号中 `opbnb`、`s coin`、`zkpol` 无同名报价；客户端还会按 unit 别名匹配，不能仅凭同名缺失推断具体资产完全无报价。[脱敏响应摘要](device-test-reports/evidence/2026-09-11-gap-audit/market-completeness.json)。
- 第一轮物理脚本仍要求 `priceRefreshFailed == false`，两端因此失败。更新为核对完整与不完整响应各自的正确时间／文案，重新运行均通过；未删除加载结束、资产详情、无同步横幅和导航断言。
- 最终截图检查发现，有部分有效报价时显示“行情不可用”容易造成误解。因此新增中英文 `Partial prices`／`部分行情`，从 provider 接到真实 WalletBoard，并补两项窄屏大字号测试；上述全量和双真机结果均为这项修正后的重新运行。
- 设备安装最终状态及源码哈希见[结构化验收](device-test-reports/evidence/2026-09-11-gap-audit/validation.json)。物理验收日志只归档固定检查标记，不提交原始会话／网络日志。
