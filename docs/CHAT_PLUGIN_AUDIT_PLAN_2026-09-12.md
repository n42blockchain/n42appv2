日期：2026-09-12。状态：M0–M7 首轮审计与客户端修复已执行；服务端依赖和未完成项按台账继续追踪。

## 审计基线与判定口径

- 钱包基线：`6ffa34e2`；声明的 Chat 依赖：`fa08010e`。
- 实际构建通过本地 override 使用 `packages/n42_chat`。初查其 `lib/` 相对声明版本有 38 个修改、3 个新增文件；必须先对齐实际交付源码。
- 正式 Chat 仓库使用隔离工作树 `../n42_chat_audit_20260912`，分支 `fix/chat-entry-audit-20260912`。保留相邻 Chat 工作区的未提交台账和截图测试。
- 正式仓库有 322 个测试相关文件，宿主缓存只有 60 个；同步宿主源码时保留正式仓库完整测试，不能以缓存测试代替插件全量验证。
- 每项功能分别记录：实现、DI/配置、UI 入口、操作回调、持久化/服务端、权限、测试及设备证据。存在类、回调或枚举不等于可用。
- 区分：实现被删除、入口被合并、入口受配置隐藏、按钮未对接、服务不可用、仅待验证。通过历史提交确认曾被精简的功能，不凭印象恢复旧代码。
- 未解决问题统一记录在正式 Chat 仓库 `OPEN_ISSUES.md`；本计划和竞品报告引用该台账，不另建相互冲突的问题清单。

## 已有证据，等待模块处理

1. `ExpressionPanel` 与 GIF/贴纸发送回调仍存在，底部分栏目前主要使用图标；需验证真实可发现性和安全区域。
2. 宿主 `chat_initialization.dart` 显式关闭 AI、Giphy、Tenor 代理模式；相关直接 key 为空时部分 DI 不注册。需核实发布配置，不通过展示按钮假装服务已恢复。
3. AI 助手按钮以 `IAiRepository` 注册为显示条件，直接 AI 路由却读取该仓库；需要覆盖未配置路由。
4. 消息菜单采用大面积多行图标网格和约 450px 固定高度估算；需要用实际内容尺寸和平台输入方式验证，再精简呈现。
5. 旧行业报告混合了代码存在、编译通过、真机通过与市场判断；旧 Roadmap 还描述已过期的依赖 pin。更新报告时保留历史记录并明确当前证据优先级。

## 行业对比方法

重点比较 Telegram、WhatsApp、Discord、Signal、Element、LINE、微信和 iMessage。
优先查官方产品文档、帮助中心、发布记录和协议文档，记录检索日期、功能限制和来源。
先比较表达能力、AI、回复/线程、群管理与菜单交互，再延伸到媒体、隐私、通话和开放集成。
追赶排序优先恢复已有但难以使用的功能，其次修复业务闭环，最后补真正不存在的新能力。
不继续沿用无验证依据的“领先/持平”评分，也不把竞品测试版或区域限量功能写成普遍可用。
