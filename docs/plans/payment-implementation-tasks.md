## P10 实施细分与审查结论

当前 `N42WalletBridge.requestTransfer` 仍按 symbol 选择首个匹配币种并先转 double；新的支付入口不得复用此选择方式。`SendParams` 已有精确 `valueWeiOverride` / `tokenValueWeiOverride`，无需创建第二套签名器，但需逐条确认使用方遵守这些参数。

- **P10b：资产解析（已提交 `84105d834`，12测试）**。从当前钱包的可信链配置构造 namespace/network/contract，返回唯一匹配币种；同名跨链、缺少链ID、重复冲突记录须明确拒绝，不能猜测。此段只解析，不签名。
- **P10c：精确发送参数**。将已选择资产与 `PaymentAmount.units` 接入已有 sender 精确金额字段；验证 ERC20 calldata 与 BigInt 一致，不经过 double 往返；独立测试超过浮点精确范围的金额。
- **P10d：旧接口歧义保护**。保留旧调用签名，但多个 symbol 匹配时提示选择网络和资产；单一匹配行为回归。新接口提供显式资产身份。
- **P10e：账户与授权复核**。确认页呈现网络/合约/金额/费用；签名前复核活动钱包、资产、余额、报价到期与设备授权，换号/过期不得继续。通过后才能进入 P12 公共测试网验证。

P10b纯解析已完成，P10c–P10e仍为后续方案；尚未完成入口接线或真实签名验证。人工签约不阻碍以上本地工作。

本轮存储队列生命周期独立修复 `8aebb3071`，11测试通过；转账恢复页面使用实际client endpoint隔离记录。恢复仍依赖原服务端账本，不保证SharedPreferences在突然断电后的落盘。
