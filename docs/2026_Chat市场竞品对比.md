## 研究范围与对象

本报告选取 2026 年全球 MAU 排名前十（且形态各异）的主流即时通讯应用作为参照，横向对比本仓库 `packages/n42_chat/` 的现有实现。

n42_chat 技术底座：Matrix 6.0 协议 + vodozemac（Olm/Megolm）E2EE + WebRTC/LiveKit + Drift ORM + BLoC + GetIt/Injectable + GoRouter，跨 iOS/Android/macOS/Windows/Web 五端，374 个 Dart 文件，24 个核心服务，19 个 BLoC，26+ 页面模块，内置 14 种语言本地化。

## A.1 勘误：¹ 三行 ✅ 曾隐藏一处真实回归

2026-04 报告把 **Emoji / 贴纸 / GIF** 在 n42 列均标 ✅——**框架层属实**（组件、数据层、BLoC 事件齐全），但 2026-06 复盘发现**实际可用性存在回归**，对用户表现为"功能似乎消失了"。根因四点：

1. **GIF 实际为"哑"**：依赖编译期 `String.fromEnvironment('GIPHY_API_KEY')` + `giphyUseProxyEndpoint:false`。正常构建未传 `--dart-define` 时，GIF 面板直接显示"请配置 key"。
2. **贴纸面板默认空**：`getInstalledPacks()` 读 Matrix 账户数据、新用户为空；商店是 TODO + 示例，且示例"贴纸"实为 `url:'emoji:🐱'`（emoji 当图），无真实素材。
3. **入口埋藏**：贴纸 / GIF 被收进"+"附件菜单，不在表情面板分页里（不符合微信/TG/WA 的统一表达面板惯例）。
4. **显示链路缺陷**：`m.sticker` 是独立 event type（无 `msgtype`），而 metadata extractor 按 `msgtype` 分支 → 贴纸 URL 未提取、未映射 `MessageType.sticker`，已发贴纸被当文本渲染。
