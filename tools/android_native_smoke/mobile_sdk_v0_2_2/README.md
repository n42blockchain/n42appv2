# Maintained Android MobileSdk v0.2.2 rebuild

`rebuild.sh` fetches the immutable [N42 mobile-sdk-v0.2.2 tag](https://github.com/n42blockchain/N42-rs/releases/tag/mobile-sdk-v0.2.2) at `2099ec735a658ba1db97c49b77a6c58c1fc82920`, applies the patches here, and builds arm64-v8a and x86_64 native libraries. It combines them with the official release AAR's unchanged Java classes and metadata. The selected maintained AAR is **not** the unchanged supplier binary. The official input AAR SHA-256 is `97ab0b5e9665998f4387e09b812db4b05116ab9d49244182ccd2e8a1cba75646`; the selected maintained output SHA-256 is `ec2dce904f925ca044089164e6b7e7821ded77788c214676a18ed357f27e87a5` for the recorded build. Binary byte identity on another host is not promised.

Usage on an isolated build host with Rust 1.97.1 (`8bab26f4f`), cargo-ndk 4.1.2, Android NDK 28.2.13676358, and libclang:

```sh
./rebuild.sh /absolute/new/workdir /absolute/official-mobile-sdk-v0.2.2.aar \
  /absolute/android-sdk/ndk/28.2.13676358 /absolute/llvm/lib
```

The work directory must be absent. The script fetches tag commits from the upstream repositories, not a sibling checkout or floating branch. It checks the N42 and [Reth v1.4.3](https://github.com/paradigmxyz/reth/releases/tag/v1.4.3) commit `fe3653ffe602d4e85ad213e8bd9f06e7b710c0c5`, downloads three exact crates.io archives with SHA-256 checks, copies the pinned `Cargo.lock`, runs `cargo fetch --locked`, and builds offline with `--locked`. Both targets use Android API 23 and linker `-z max-page-size=16384` plus `-z common-page-size=16384` flags. The source has its own Git metadata, so build scripts cannot accidentally stamp the app repository revision. After applying source patches it is intentionally dirty; retain the base commit, patch hashes, lock hash, compiler and artifact hash with a released binary.

The supplier's tagged lock omits the `mobile-sdk` workspace package and cannot build this package with `--locked`. `Cargo.lock` here is a controlled repaired and updated graph (SHA-256 `7e255879661c166546a70e21c0fa7d2e8cb76705a0d4a5fd214d48630db630ca`), not a claim of official binary reproducibility. The declared workspace Rust floor is 1.90 after the patched `ruint` update; the recorded build compiler is 1.97.1. `n42-source.patch` keeps the called JNI and C exports, uses `ethers-core` for actual transaction ABI/types, and adds the Android same-library TLS verifier initialization entry. Full `ethers` and signers remain for examples/dev. `reth-dns.patch` adapts the exact Reth parent to Hickory 0.26.3 without changing N42's DNS request protocol. The three crate patches update an Alloy serde re-export, discv5's LRU parent constraint, and build-time vergen-git2's git2 parent/API. No patch changes trust checks to permissive roots or alters `runClient` behavior.

The packaged Android app also includes the published JVM companion from `rustls-platform-verifier-android 0.1.1` (`rustls:rustls-platform-verifier:0.1.1`), AAR SHA-256 `667292cadd8fa589229dd0f716541236a761f29b774930868d218175633830fd`. App startup does not load this SDK. On supported 64-bit processes, every Rust `runClient` route initializes the verifier with application Context before network work; certificate validation remains Android's normal trust path. The fixture-only `ffi-testing` feature, mock certificates and test JNI methods are absent from this lock/source patch/output AAR.

Source terms visible in the pinned inputs: N42 root `LICENSE` is MIT and the mobile-sdk manifest declares `MIT OR Apache-2.0`; Reth has `LICENSE-MIT` and `LICENSE-APACHE`, and the copied DNS crate inherits its dual-license workspace declaration. `alloy-consensus 1.0.12` and `vergen-git2 1.0.7` declare `MIT OR Apache-2.0`; `discv5 0.9.1` declares Apache-2.0. Preserve the upstream license/notice files with the corresponding downloaded source archives and this patch set when redistributing the maintained native artifact. This records those package declarations and rebuild inputs; the terms of every transitive dependency and the combined app distribution were not adjudicated here.
