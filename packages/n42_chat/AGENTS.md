# Repository Instructions

## Open Issues Ledger

- Use `OPEN_ISSUES.md` in the repository root as the single source of truth for unresolved issues from active work.
- Before finishing a task, update `OPEN_ISSUES.md` when there is any unresolved bug, unsupported path, partial implementation, or meaningful verification gap.
- Do not duplicate existing entries. Update the matching item instead, including severity, current behavior, and next step when they change.
- Remove an item only after the fix is implemented and verified, or mark it `Resolved` if keeping short history is useful.
- Do not add speculative concerns. Only record issues that were actually observed, intentionally deferred, or left unverified during the work.
